# Maintenance and security review — 2026-10-22

Scope: the application at commit `756ca9964f34d059dc2aa17240821ed0ba6bec25`,
with fixes prepared for 0.3.0. Tests use synthetic vaults and fabricated
credentials. No personal vault or device Local Key was read, migrated,
rewritten, or uploaded during this review.

## Findings addressed

| Area | Previous problem | Result |
|---|---|---|
| Backup recovery | Every key slot was omitted, so a restored managed database could not be unlocked from the archive and master password alone | Version 2 includes the encrypted password slot; real source-loss recovery is tested. Version 1 accurately requires a surviving original slot |
| Archive validation | Missing/duplicate/non-regular members could pass incomplete validation; extraction could leave partial output | Verify and restore share full validation; fixed allowed names are written to private staging before publication |
| Untrusted KDF metadata | Arbitrary Argon2 costs could reach native allocation/work | Strict integer/range/work validation before derivation; encryption field sizes and encodings are checked |
| Persistence | Predictable JSON temporary paths allowed shared files or symlink interference; flush/fsync was absent | Unique exclusive private temporary files, fsync, and atomic replacement |
| Vault writes | Direct creation could overwrite a database; stale handles could overwrite newer changes; library temporary filenames were shared | Exclusive creation, private atomic saves, a stable advisory lock for ASH writers, and fingerprint conflict detection |
| Adoption | An external USB key was not placed where later logins expected it; key paths could escape the selected USB | Copy the existing key into the managed layout, preserve originals, reject overwrites and paths outside the USB, retain rollback backups |
| Auto-Type | Substrings and broad regexes could become HIGH confidence; input could continue after locking or an application switch | Only exact class matches become HIGH; partial/regex matches require confirmation; check cancellation and detected class between steps |
| Secret lifetime | Guard/no-backend/factory-failure paths could retain secrets or leave async completion hanging | Wipe on every completion path and deliver a generic failure on backend exceptions |
| Clipboard and locking | Separate copy owners escaped immediate session cleanup; lock cleanup cleared unrelated clipboard contents; wall-clock changes affected inactivity | Share session clipboard ownership, honor timeout settings, preserve unrelated values, request the sensitive hint, and use monotonic elapsed time |
| Entry editing | Saving an unrelated edit overwrote custom Auto-Type targets; website URLs were not editable | Preserve and edit existing targets and URLs; show save errors and retain a new entry's UUID for retry |
| TOTP and generation | Invalid stored TOTP could crash account viewing; verification near epoch could use a negative counter; custom symbols bypassed ambiguity filtering | Validate configurations, safely treat invalid stored TOTP as unavailable, skip negative counters, consistently filter symbols |
| Accessibility input | Missing accessibility bus could abort Python; text entry used an invalid unused call; navigation always returned unavailable | Probe bus first, use EditableText directly, honor rejected writes, delegate navigation to available ydotool |
| Health and packaging | Missing slots were absent from manifest comparison; malformed manifests could crash; installer build upgraded tooling implicitly | Compare recorded and current file sets, report malformed metadata, build with explicit installed tools, inspect wheel contents |

## Feature preservation

Existing KDBX storage, AES-256/Argon2id, and key-slot formats remain in use.
No vault migration is required. Retained areas include setup/adoption,
password and Local Key login, device enrollment/revocation/password reset,
USB recognition/removal handling, multiple vaults, account search/categories,
passwords/notes/URLs/tags, TOTP and QR import, recovery codes, both password
generators, Auto-Type strategy editing/presets/testing, themes/settings,
shortcuts, the optional agent, legacy commands, and packaging. Existing
coverage remains, with 46 additional focused regression cases.

A database-engine rewrite was unnecessary: the major failures were in
backup composition, persistence, input handling, and UI integration.
Preserving the encrypted engine avoids a new data migration and retains the
existing feature model.

  display-dependent activation tests and two unavailable live UDisks2 tests.
- Two warnings originate in PyGObject's use of deprecated Python asyncio
  policy APIs; they are not test failures.
- Regression tests include real encrypted backup → source deletion → restore
  → password-slot unlock → all entry fields, plus legacy backup recovery,

- The self-extracting installer builds with no dependency downloads; its
  `--help` path executes successfully. No application installation or service

- The standalone demo creates and reopens four synthetic accounts, verifies

  builds the wheel, checks its contents, and builds the installer. Its live

  The complete pipeline result remains separately visible in GitHub Actions.

## Verification limits and compatibility

Interactive visual QA, physical USB unplug/replug, real GNOME/KDE/Hyprland
input, a fresh end-user installation, and a complete Arch package installation
were not exercised in this environment. Automated tests are not an
independent cryptographic audit or a guarantee that every bug is absent.

Old backups retain their snapshot's master password. Version 1 archives
require a surviving original password slot; see [BACKUP_RECOVERY.md](BACKUP_RECOVERY.md).
A browser application class does not prove website identity. Cancellation
stops future input steps, but cannot recall input a subprocess already sent.
Advisory writer locking coordinates ASH instances; other applications may
ignore it. Filesystem crash durability remains subject to the USB and OS.

Implementation references: [PyKeePass documentation](https://pykeepass.readthedocs.io/en/latest/)
and [argon2-cffi low-level API](https://argon2-cffi.readthedocs.io/en/stable/api.html).
